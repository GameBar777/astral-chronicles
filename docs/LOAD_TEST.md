# 負荷試験 50 / 100 クライアント（PHASE 10, 2026-11-12 JST）
条件: 開発箱1台、dev サーバー（tsx、NODE_ENV=development）1プロセス + PostgreSQL 同居、別ポート 2587 で起動（`LOADTEST_AUTH_LIMIT=2000` で認証レート制限のみ緩和、本番では無視）。
全ボットをアステリアの広場（スポーン地点）に配置し、30秒間 8Hz で左右に歩行（壁に当たれば反転）。
```
LOADTEST_AUTH_LIMIT=2000 SERVER_PORT=2587 npx tsx server/src/index.ts &
HTTP=http://127.0.0.1:2587/api WS=ws://127.0.0.1:2587 N=100 DURATION=30 node server/scripts/load10.mjs
```

所見・制約（隠さず）:
- 1プロセスで100人同一マップでも遅延 p99 < 100ms、取りこぼし0。負荷生成も同じ箱上のため実ネットワーク遅延は含まない。
- 試験は「移動同期」のみ。戦闘・チャット・市場を同時に回す混合負荷、複数プロセス/水平分割（hub はプロセス内レジストリ＝単一プロセス前提, TD-014）は未試験。
- 初回試行では前回位置が壁際に残ったボットが壁に押し付け続け「blocked」補正が多発した（試験スクリプト側の問題）。スポーン配置リセットと壁反転を追加して再測定した値が上表。

# 混合負荷試験（戦闘 + チャット + 市場, 2026-11-12 Asia/Tokyo）
`npx tsx server/scripts/load-mixed.mjs`（N/DURATION/MIXED_PORT で変更可）。スクリプト自身が `createGameServer` をポート 2588 で起動する（認証・行動・戦闘・移動のレート制限を試験用に緩和。本番の `index.ts` ではこれらの緩和は入らない）。
4人が草原で連戦、4人がアステリアで歩行しながらローカルチャット（スパムガード内）、4人が薬草の出品・購入・価格履歴を同時に叩く。

| 項目 | 結果 |
|---|---|
| 同時クライアント | 12（戦闘4 / チャット4 / 市場4） |
| 時間 | 25秒 |
| 戦闘開始 / 終了 / ターン | 3574 / 3573 / 7986（戦闘ボットは勝利・敗北後すぐ再戦。敗北後は草原へ戻す） |
| ローカルチャット送信 / chat_error | 28 / 0 |
| 出品 / 購入 / 履歴GET | 107 / 106 / 215 |
| 移動送信 / 座標補正 | 280 / 0 |
| 予期しないエラー | 0 |
| サーバーRSS（試験プロセス内） | 119→335MB（戦闘ログの大量 INSERT が主因） |

所見・制約（隠さず）:
- 初回実行では市場の交差購入（AがBの出品を、BがAの出品を同時に買う）で `40P01` デッドロックが多発した。`buyListing` が買い手行を先にロックしてから売り手の所持金を更新していたため。買い手・売り手を `id` 順でロックするよう直し、`tx()` は `40P01` / `40001` を最大3回再試行する。回帰テスト `crossed concurrent buys` を `phase11-shortfalls` に追加。修正後の上表ではデッドロック 0。
- 戦闘ボットはクライアント側の演出待ちなしで再戦するため、実プレイより高い戦闘 TPS。チャットはサーバのレート制限（10秒に5通、同一文15秒）に合わせ 2.5秒間隔。
- 負荷生成も同じ箱上。複数プロセスの hub 分割（TD-014）は対象外。
